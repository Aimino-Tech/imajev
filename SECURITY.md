# Security policy

Do not open a public issue for vulnerabilities involving credentials, private data, arbitrary code execution, dependency compromise or remotely exploitable service flaws. Use GitHub private vulnerability reporting when available; otherwise contact maintainers privately.

Include affected commit, configuration, reproduction, impact and mitigation. Never include customer data, API keys, access tokens, private images or proprietary prompts.

Model-quality and benchmark regressions are normally correctness issues, not security vulnerabilities.
